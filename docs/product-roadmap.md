# DogeOW Chat 产品迭代

首版形态：单社区、自部署、可嵌入站点。多租户 SaaS 和订阅计费不属于本次首版范围。

目标：面向社区与网站嵌入场景，提供可独立访问、可由网站账号统一登录的聊天产品。界面优先呈现房间与对话，成员、搜索和管理按需打开。

## 交付原则

- 每个入口连接真实 API，覆盖权限、加载、成功、失败和重试状态。
- HTTP 历史、发送回包和实时广播采用一致的消息结构。
- 登录、房间权限、私有广播、引用消息必须遵守同一房间边界。
- 手机、平板和桌面均可完成核心操作；键盘与中文输入法可用。
- 经过自动化测试、浏览器操作及窄屏检查后再标记完成。
- 代码验证与线上部署分开记录。涉及数据库变化时提供迁移说明。

## 当前任务

### 1. 社区对话与简洁界面（已实现）

- 真正的消息引用回复，删除原消息后的引用占位。
- 自己的消息编辑、删除，以及管理员删除；实时同步。
- 表情回应的添加与取消，服务端持久化、幂等处理。
- 搜索整个房间的历史，分批加载、失败重试、从结果回复。
- 收起常驻成员侧栏，整合房间信息与管理入口。
- 登录用户才能订阅房间消息，非成员和被封禁用户不能新订阅。

### 2. 房间与社区运营（已实现）

- 私有房间邀请链接、有效期与撤销。
- 成员管理、举报处理、禁言与封禁操作的完整界面。
- 未读与最后阅读位置的服务端同步。
- 默认房间、邀请加入、空白状态与失败重试。

### 3. 网站接入（已实现）

- 嵌入主题、尺寸、默认房间、可靠登录恢复与宿主事件接口。
- 附件上传、访问权限、大小类型限制、失败重试及存储清理。
- 站点精确 Origin 授权、宿主消息来源校验和上传限制。
- 浮窗关闭与重新打开、未读角标、按实际可见性同步已读。
- 分账号保存房间状态与草稿，退出后不自动重新登录。

### 4. 生产环境验收要求

- 配套数据库迁移、前后端发布及广播/队列进程重启。
- 真实身份服务、域名、Cookie 策略下的登录和嵌入验收。
- PostgreSQL/Redis 容量测试、数据导出与保留策略、备份恢复演练。
- 日志告警、广播故障补偿和存储容量监控；当前没有持久化广播补偿队列。

本轮在隔离 SQLite、真实 Laravel API、Sanctum 测试账号和 Reverb 环境进行双账号浏览器联调，并在独立 PostgreSQL 测试库通过新增消息、附件、邀请、已读及举报接口测试。自动发布流水线的成功不替代真实身份、容量和恢复验收。多租户、订阅计费和商业 SLA 不属于此版交付。
